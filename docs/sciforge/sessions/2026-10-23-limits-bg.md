# Session log: limit searches in the background (branch `wf/limits-bg`)

To be copied into MEMORY.md by whoever merges (this branch does not edit MEMORY.md). Started
from `experimental` (8af46ba). No FreeCAD core file changed (nothing for `core-patches.md`).
The session was short (Luca had 45 minutes): what is done and what is not is listed honestly.

## What changed (plain language)

**Task A: a limit search never freezes a dragged handle, in more dialogs.** When a value goes
past what fits (a wall too thick, a radius too big), the dialog looks for the largest value
that fits by building trial versions. Until now only Draft did this "in the background" (one
trial build per turn of the event loop, so the handle keeps moving between builds). Other
dialogs did all the trial builds at once, which froze the handle for the whole search.

Now the same background search is shared (`value_limits.LimitedValues`): a dialog calls
`limit_refuse()` where it called `limit_refused()`, `limit_waits()` at the start of its
preview and `limit_accept()` / `limit_accepted()` around OK. While the search runs:

- the dialog says "Finding the largest value that fits…" (or "…angle…" for angles);
- no trial is built while the mouse moves with the button held (the handle stays free);
- dragging back below the nearest value found not to fit stops the search (as in Draft);
- when it ends the value is held at the limit (if it is still past it) and previewed, now or
  once the mouse rests;
- OK during a search finishes it at once with a wait cursor, then takes the held value; OK on
  a new refused value searches at once (one press, as in Draft);
- closing the dialog (OK, Cancel, Undo) cancels the search: nothing is left running.

Wired into: **Shell**, **Pipe**, every **primitive dialog with limits** (`PlacedPanel`:
Torus, Coil, Gear...), **Thicken**, **Press Pull** (faces, fillet, edit blend), and **Fillet /
Chamfer** (including sets and variable radius: their own search code got the same background
version: `FilletPanel._limit_start` / `_limit_ended` / `_limit_stale`).

Also fixed on the way: a value typed past the limit and not yet left (the box still shows the
typed number) was remembered as "a value that works" when the held value's preview worked;
a later search then used it as its start and reported a wrong limit ("Smallest that fits:
50 mm" in `limits_presspull`). `limit_good()` now remembers the held value.
`limit_hint()` never starts a second search while one runs in the background.

**Not done (left as they were: search at once):**

- **Extrude taper / thin wall** and **Revolve**: their trial builds happen in the document's
  own feature (then put back); running them one per event-loop turn would show every trial
  (and failing ones) in the view and needs the restore to move to the search's end or
  cancel. Needs its own careful change.
- **Sketch fillet / chamfer**: they use `Limiter` directly (2D trials, cheap); not wired.

**Task B: cheaper failing trials (Draft): measured, not changed.** The idea was to check only
the faces the draft changed (and their neighbours) first: a fault found there is a fault of
the whole solid (BRepCheck runs the same checks on the same faces, edges and vertices), so a
failing trial could stop early, and a passing one still gets the full check (the answer is
always the full check's: the limits cannot change). Measured on a 234-face part (100 x 60 x
30 block, rounded corners, 64 recesses and 64 holes, 8 outer walls drafted):

| check | sound angles | broken angles |
|---|---:|---:|
| whole solid (`isValid`) | 43-67 ms | 38-48 ms |
| drafted faces + neighbours | (then the full check too: +40-60 ms) | 39-41 ms |
| drafted faces only | 28-30 ms | 24-25 ms, but **misses** the fault at 12-20 deg |

FreeCAD's Draft gives every face a new identity (no face is "the same" as before), the
neighbours of the drafted walls are the top and bottom faces that carry every hole, and they
dominate the check. So the safe local check is no cheaper on failing trials and costs more on
passing ones; the cheap one is not safe. Reverted (`drafting.py` unchanged). (Numbers from
this sandbox, only to compare the checks with each other; Luca tests speed on his PC.)
