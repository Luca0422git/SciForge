# 2026-10-21: values past what fits stop at the limit (branch `wf/limits`)

To be copied into MEMORY.md by whoever merges (this branch does not edit MEMORY.md).

Luca's request (approved): "Whenever I'm editing an object, if I go past the limit of a
draft or chamfer or fillet, it just gives me an error and I have to manually fix the value.
The error already gives the limit. So instead of giving an error and not letting me finish
until I fix it, limit edits to stop at that limit, so if I want to chamfer something to the
max I can quickly drag it without having to type whatever obscure value the error spits
out." And: "add the functionality to any tool that can give that sort of error."

**Decision (Luca, 2026-10-21): this deliberately differs from Fusion**, which shows an error
and waits. Recorded at the top of each parity doc concerned (`docs/sciforge/parity/fillet.md`,
`shell-draft-scale.md`, `extrude-presspull.md`, `primitives.md`, `gear.md`, `surface.md`,
`revolve.md`, `sketch.md`; `hole-thread.md`, `sweep-loft-rib.md`, `mesh.md` say why they are
not held).

## What Luca sees (plain words)

- Drag an arrow (or the draft / taper disc) past what fits: it stops there, like the end of
  a slider. The preview shows that result and a blue line under the dialog's message says
  "Largest that fits here: 3.47 mm" ("Furthest that fits here: -9.99 mm" for a push into the
  part or a negative angle). OK works at once.
- Type a number that is too big (or too far the other way): the dialog uses the limit and
  says "5 mm does not fit: limited to 3.47 mm". The box keeps what you are typing and shows
  3.47 once you leave it (Enter, Tab, a click elsewhere).
- Drag back below the limit: the value follows again and the blue line goes.
- A value that comes from a parameter or formula ("width / 2") is never rewritten (that
  would break the formula): the red explanation stays, now with "Largest that fits here:
  ..." added, and OK waits, as before.
- Nothing about it goes to the Report view.

## How it works (`src/Mod/SciForge/sciforge/value_limits.py`, pure Python, unit tested)

- `search(works, good, bad, step)`: bisection between a value that works and one that does
  not, time budgeted (1.5 s, at least 3 builds). The result is rounded toward the safe side
  to the box's precision (FreeCAD's "Decimals" preference, 0.01 mm by default; 0.1 degree)
  and that tidy value is built once more (the bisection can stop right on the failing edge;
  a jumpy kernel gets the next tidy value toward safety). It also tries the tidy value just
  under the refused one (2.50 rather than 2.49).
- `LimitCache` / `Limiter`: the limit is kept per set of inputs (`make_key`: the part before
  the step, the picks, every other value of the dialog) and per side (above / below) and side
  of zero. Every drag step only looks it up (`clamp`), nothing is built; another set of
  inputs (an edge added, Inside changed to Both) finds its own limit once. A search that
  finds no limit (a refusal a smaller value does not cure) is remembered too.
- `is_limit_error(text)`: only refusals of the "too big / too thick / use a smaller ..." kind
  start a search; anything else (a face that cannot be drafted at any angle, a missing pick)
  stays an error.
- `LimitedValues`: the mixin most dialogs use (Shell, Draft, Press Pull, Thicken, the
  primitives, Gear, Coil, Pipe, Extrude): `limit_edit` for every new value (typed / dragged /
  formula), `limit_refused` when the preview was refused (holds the value, the dialog previews
  again), `limit_good` when it worked, `limit_hint` for a formula's error. The Fillet dialog
  has the same logic written for its sets (`fillet_ui.BlendPanel._hold` / `_limit_refused`).
- `note_label()` / `show_note()`: the blue line (a separate label under the message, so the
  red message and its tests are untouched); `ShowWhenLeft` / `show_held`: a typed number held
  while it is being typed is shown as the limit once the box is left.
- A limit holds only values on its own side of zero: a coil's height may not get too small
  going down, yet dragged through zero it is a coil the other way (found by
  `primitives_qa_coil`).

## Audit: which tools got it

| Tool | Values held | How the limit is checked |
|---|---|---|
| Fillet | Constant radius, Chord Length, Variable start / end / point radii, Rule radius; FreeCAD's step and SciForge's sets (the set being edited) | `blend.check_build` / `fillet_sets.compute` (no document) |
| Chamfer | Equal Distance, both distances of Two Distances, distance and angle of Distance and Angle | same; Distance and Angle as the equivalent Two Distances bevel (see findings) |
| Draft | Angle, Angle 2 (the handle stops too; the 89.9 stop stays) | `drafting.check` + `draft_shape` (also the other bodies) |
| Shell | Inside / Outside Thickness (also other bodies) | `shelling.trial` |
| Press Pull / Offset Face | distance both ways; Q on edges: the new fillet's radius; a fillet / chamfer face: FreeCAD's step's size | `presspull_core.press_pull`, `blend.check_build` |
| Thicken | thickness both ways | `surface_geom.thicken` (now refuses folding, see findings) |
| Extrude | Taper Angle (side one, side two), thin Wall Thickness (both) | the extrude built in the document (FreeCAD's Pad / Pocket refuse the taper) |
| Torus, Coil, Pipe | torus / inner diameter, coil section / angle / pitch, pipe thickness / section size | the dialogs' pure checks (`primitives_core`) |
| Gear | hole, root fillet, backlash, rim, rack height / length (not the number of teeth: a whole number) | `gear_core.check` |
| Revolve | Angle, Angle 2 typed past 360 / 180 a side / 360 together (the arrows already stopped there) | the fixed rules |
| Sketch Fillet | radius (pointer far out or typed; Enter makes the largest fillet) | `sketch_fillet_core.check` |
| Sketch Chamfer | Distance, Distance 2 between two lines | `sketch_chamfer_core.check_fits` |

Not held, and why (also in the parity docs): Press Pull's Modify Existing Feature (the
extrude's own length) and a size of SciForge's own fillet step clicked with Press Pull;
sketch chamfer's angle and line-arc chamfers; Hole / Thread (their refusals depend on several
values together; the thread's arrow already stops at its face); Sweep taper / twist, Rib,
Web, surface Offset / Extend / Extrude taper (candidates for a later pass); MESH > Shell (its
message names the thinnest size, no handle); Box / Cylinder / Sphere / Scale / sketch Offset
have no such limit.

## Findings (bugs found on the way)

- **OpenCASCADE segfault**: FreeCAD's Distance and Angle chamfer crashed FreeCAD
  (`ChFi3d_Builder::PerformSetOfKGen`) for a size where the bevel runs into a fillet (box
  40 x 30 x 10, front top edge filleted 9.99, chamfer of the right top edge at distance 10).
  A user dragging there would crash too. `blend.check_build` now checks such a chamfer as
  the equivalent Two Distances bevel (law of sines in the corner's triangle), and the Chamfer
  dialog checks a Distance and Angle chamfer before building it (no longer "optimistic").
- FreeCAD's Distance and Angle chamfer that did not fit kept the last good shape and the
  dialog showed no reason (the trial could not build it): now explained / held.
- **Thicken made bogus solids**: a round wall of radius 10 thickened 50 mm inward came out
  as a "valid" solid of 47124 mm3 (through the axis). `surface_geom.folds_at` now refuses an
  offset that passes a centre of curvature (sampled on each curved face).
- The taper / draft disc (`extrude_ui.AngleDragger`) took its own read-back rounding (80 came
  back as 80.0000026) for a turn: a formula typed in the Draft angle box was dropped at once.
  `set_angle` now remembers the angle as read back.
- Pre-existing, not changed: FreeCAD's own Draft at 85 degrees on the box's front face gives a
  strange but "valid" result while 80 fails (non-monotonic); a revolve angle from a formula
  over 360 is silently clamped to 360 by FreeCAD's property; `shell_draft_qa_draft` crashed
  or hung on the base commit in this sandbox (before any change).
