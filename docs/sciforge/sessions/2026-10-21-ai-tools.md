# Session log: AI tools (workflow agent 1 of 3, branch `wf/ai-tools`)

To be copied into MEMORY.md by whoever merges (this branch does not edit MEMORY.md).
Started from `0b1da82`. No FreeCAD core file changed (no full build needed, nothing for
`core-patches.md`).

Luca asked for "the functionality added to any tool that can give that sort of error" and for
every SciForge feature to be reachable by an AI. This session builds the tool catalogue, every
tool, a headless backend and a command line; the next agents continue from this branch.

## What was built

1. **One catalogue for every AI tool** (`sciforge/ai/catalog/`, plain Python, no FreeCAD):
   109 tools, each defined once with `registry.define()` (name, title, category, ribbon tab,
   description, JSON schema, examples, the ops it makes or the action that runs it, what it
   needs: an open design / a solid / the window / a drawing, read-only or destructive).
   - The MCP server, the chat panel (every provider), the bridge, the headless backend and the
     CLI all read it; `tools_core.py` is now only a re-export (old imports keep working).
   - The 16 original tools come first and keep their exact old behaviour (same steps for the
     same arguments, same error sentences); they gained Fusion's options (extrude To Object /
     two sides / thin / start offset, revolve To, single holes and every hole option, shell
     inside / outside / both, export IGES / OBJ / BREP / DXF / ASCII STL, ...).
   - New groups: sketches (curves, add to sketch, constraints, dimensions, polygon, trim, text),
     create (sweep, loft, rib, web, emboss, thread, primitives, coil, pipe, gear, patterns,
     mirror, hardware), modify (press pull, fillet sets, rule / full round fillet, draft, scale,
     combine, split, replace / delete face, move / copy, align, materials, appearance),
     construct (planes, axes, points), assemble (components, joints, ground, drive),
     inspect (mass properties, centre of mass, interference, sections), timeline (get / edit /
     roll / suppress / delete / move / rename / group steps, parameters), documents (new,
     open, save as, close, switch, import), drawings (create, views, dimensions, notes, export),
     the view (set / get / named views / show-hide), get_help and list_tools.
   - Validation: a JSON-Schema subset plus SciForge's selectors; every problem is told in one
     sentence ("Not done: ...").
   - Provider limits: OpenAI and Gemini get the first 128 tools, a local model 48, Anthropic
     all (the 16 originals first, then the most useful ones: `catalog.CHAT_ORDER`).
2. **Executor** (`sciforge/ai/executor.py`, `sciforge/ai/actions/`): one `run(tool, args, host)`
   for every caller: validate, check what the tool needs, then build its steps with the ops
   Builder or run its action. Each design change is one Undo step named "AI: ...". A fillet /
   chamfer made while the timeline marker is rolled back is inserted there. The host decides
   what differs between the window (`bridge.GuiHost`: active body, questions to the person,
   SciForge's saving with versions, screenshots) and no window (`executor.Host`).
3. **Headless backend and CLI** (`sciforge/ai/headless.py`, `sciforge/ai/cli.py`,
   `tools/sciforge/sciforge-cli`): `sciforge-cli info|convert|run|tools|mcp`, with no window.
   `run` takes tool calls as JSON (a file or stdin) and answers JSON; `convert` turns a design
   into STEP / STL / ...; `mcp` is an MCP server without the window
   (`sciforge_mcp.py --headless`). Exit codes: 0 done, 1 a tool failed, 2 bad usage.
4. **Honest MCP retries** (`sciforge_mcp.py`): when SciForge's answer is lost, a read-only
   tool is asked again (twice at most); a changing tool is not repeated, and the AI is told
   "it may or may not have been applied: inspect the design first". Validation errors are
   answered as tool results with `isError` (MCP 2025-11-25), so the AI can correct itself; an
   unknown tool stays a protocol error (-32602).

## Findings / bugs fixed on the way

- **Rib far from its sketch's origin failed** (`rib.py` `_plane_section`): the reach of the
  cutting plane ignored where the part sits; fixed, golden model `sf_rib_far_from_origin`.
- **Surface ops failed on any design with a broken object** (`ops/surface_ops.py`): they now
  fail only on objects this step newly broke.
- Sketch constraints that conflict are removed again and named in the answer (the solver's
  Conflicting / Redundant lists, compared before and after).
- Deleting a body deletes the sketches inside it, also sketches other steps use (a pipe whose
  path sketch lived in a coil's body broke). Left as is (FreeCAD behaviour); the answer names
  the steps it broke.
- Inserting an FCStd needs the design saved first (TechDraw / App::Link need a file path);
  the AI is told so.
- Headless saving has no version history (that is SciForge's window code); TechDraw PDF export
  needs the window (headless: DXF only, the AI is told).
- freecadcmd parses options itself and takes one argument after `--pass`: the CLI passes its
  arguments in a file named by `SCIFORGE_CLI_ARGFILE`, and redirects FreeCAD's banner away from
  standard output so the answers stay clean JSON.

  screenshot, save through SciForge, drawing PDF) through `bridge.call` with `GuiHost`.

  sweep_loft_rib (68), sweep_loft_qa_rib (213), surface_extrude (60), surface_patch (71) pass.
