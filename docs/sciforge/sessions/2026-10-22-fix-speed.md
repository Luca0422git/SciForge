# 2026-10-22: fixes after the review of "speed with big designs" (branch `fix/speed`)

To be copied into MEMORY.md by whoever merges (this branch does not edit MEMORY.md).
An adversarial review of item 6 (`2026-10-21-view-speed.md`) found three problems; all three
were reproduced on this branch first (headless probes and GUI scenarios) and fixed. Only
`src/Mod/SciForge/` changed: no core patch.

## In plain words (for Luca)

- **Drawings now follow Ctrl+Z / Ctrl+Y again** (F1, major). The faster Undo skipped the
  rebuild when FreeCAD had put back the right shapes, but a drawing view keeps the lines it
  projected in memory, not in the design, so after Ctrl+Z the drawing still showed the
  edited part, with the edited dimension values (a PDF made then was wrong). Now, after an
  Undo / Redo that skips the rebuild, SciForge recomputes just the things that depend on the
  restored part and keep a result outside the design's values (drawing views, sheets,
  dimensions, analyses). That takes a moment, not a rebuild of the part.
- **Recovery copies of unchanged designs are really skipped now** (F2). With two or more
  changed designs open, writing one design's copy made the others look changed, so every
  5 minutes all of them were written again (a freeze of ~2 s per big design). Now a design
  that did not change since its copy is skipped, however many designs are open.
- **Fast Undo / Redo now also works for sketch dimensions and user parameters** (F3), the
  most common edits: before, these always rebuilt the whole design (15-19 s on the test
  designs), because FreeCAD re-solves a sketch while it finishes an Undo and SciForge took
  that for a script's change, and because the parameters object "had no shape to put back".

## What was changed

- `undo_fast.py`
  - `stale_dependents()` / `_refresh()`: after a skipped rebuild, every object (in any open
    document) without a Shape that depends on an object whose Shape the Undo / Redo put back
    is touched and recomputed alone (`doc.recompute(objects)`: the part is up to date, so
    only they run). Left out: objects that compute nothing (groups and components, links,
    the origin, `App::VarSet`, spreadsheets: their values are in properties the Undo put
    back). Their own changes are not counted by the ledger (they feed no shape), so the
    next Undo can still be fast. If the refresh fails, the steps are touched again and the
    caller rebuilds as before.
  - The ledger treats changes a sketch makes after FreeCAD applied an Undo / Redo and before
    it signals it (`SketchObject::onUndoRedoFinished` runs `solve()` there, with FreeCAD's
    "undoing" flag already cleared) as part of the Undo / Redo. Only sketches, only in that
    window: anything else (a script, an abort, a change after the signal) still counts and
    rebuilds.
  - `App::VarSet` (user parameters) counts as "its result was put back" when the Undo
    restored its values (it holds only values).
- `versions_ui.Recovery`: the change counter a copy is compared with leaves out the moves
  made by writing recovery copies (FreeCAD signals "save finished" for a copy too).
- Notes of item 6 (`2026-10-21-view-speed.md`) corrected: which edits get the fast Undo, and
  the "No existing scenario needed a changed expectation" claim.

## Which edits get the fast Undo / Redo now

Fast (no rebuild, checked against a full rebuild in the tests): a step's values changed in
its dialog (extrude distance, fillet radius...), a sketch dimension or a user parameter
changed in Change Parameters, AI `edit_step`, as long as the change was rebuilt inside its
transaction (every dialog's OK does that) and nothing changed outside a transaction since.
Still rebuilt (as before, the safe side): a design changed by a script outside a
transaction in between, a step left waiting for a rebuild when the transaction started,
a spreadsheet step, an Undo whose start SciForge did not see (the first one after opening a
file is fine; after a refused AI value it can be either), and edits made in the sketch
editor itself (FreeCAD rebuilds after leaving the sketch, outside the transaction).
