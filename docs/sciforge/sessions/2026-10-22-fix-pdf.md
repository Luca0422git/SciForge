# 2026-10-22: Fixes after the review of the better drawing PDFs (branch `fix/pdf`)

An adversarial review of item 7 (`docs/sciforge/sessions/2026-10-21-pdf.md`) found six
problems (PDF-1 to PDF-6). All six were reproduced with real FreeCAD 1.1.4 first, then
fixed. No change to FreeCAD's own files.

## In plain words (for Luca)

- **Archive PDFs (PDF/A) stay archive PDFs.** If FreeCAD's PDF preference asks for
  PDF/A, the file must follow strict rules. SciForge's additions broke three of them: the
  font it adds lacked a small "which letters are inside" table (CIDSet), the file's
  "trapped" flag was in one place but not the other, and the tiny code dots SciForge uses
  to sort lines into layers stayed in the file as red specks (Qt paints them solid in
  PDF/A). All three are fixed: the dots are always taken out, the table is there, the two
  places agree.
- **Print-shop PDFs (PDF/X-4) stay PDF/X-4.** The rewrite used to throw away the
  file's "I am PDF/X-4" label and its document ids; now they are kept. Such a file gets
  no clickable links (print-ready pages should have none); layers are fine there.
- **Centre marks stay on their layer** with TechDraw's thin line set ("FC 0.35mm"),
  where hidden edges look exactly like SciForge's centre marks (same thickness, same
  dashes). SciForge now remembers where each view's cosmetic lines (its centre marks)
  are before printing and recognises them in the PDF by their position.
- **Half the file size.** The PDF used to carry the old, unused copy of every page; now
  only what the file uses is written (a review drawing: 447 KB before, 241 KB now,
  TechDraw's own print 221 KB).
- **Every character searchable.** Letters osifont does not have (′ ″ for angles,
  Chinese, ✓...) used to vanish from search and copy; now the whole text is stored next to
  it (ActualText) so search finds it. A feature control frame's drawn symbol and
  diameter sign now read as ⌖ and ⌀ (searching "⌀0.05" finds the frame).

## What changed

- `drawing_pdf_core.py`: `enhance` reads the file's identity from its XMP
  (`kept_xmp`, `_identity_of`: pdfaid, pdfxid, xmpMM) and writes it back into the new
  packet with `pdf:Trapped` equal to the Info's `/Trapped` (`xmp(..., kept, trapped)`);
  the Info dictionary starts from the old one. PDF/A: `layer_content(..., layers=False)`
  still removes the markers and Qt's value-less `SCN`. PDF/X before X-4 gets no layers,
  any PDF/X no links; PDF/A and PDF/X get no added text when the font is not embeddable
  (Helvetica fallback). `layer_content(..., cosmetic=)`: a path dashed at the hidden
  width whose two ends are one of the view's straight cosmetic lines is "centre".
  `overlay` wraps a text the font does not cover in `/Span <</ActualText ...>> BDC`.
  `doc.prune()` before writing.
- `drawing_pdf_objects.py`: `Document.prune()` drops what the trailer does not reach
  (Length objects too, since `write` puts the length in) and numbers the rest 1, 2, 3...
- `drawing_pdf_font.py`: `TrueType.kept()` (the glyphs a subset holds), `cid_set()`,
  the FontDescriptor's `/CIDSet`; `covers()` and `embedded` on both font kinds.
- `drawing_pdf_export.py`: `add_markers(..., cosmetic)` / `cosmetic_lines()` read the
  paths of each view's last N edge items (N = cosmetic edges + centre lines; TechDraw
  adds them after the projected edges) before printing.
- `drawing_annot_core.py` / `drawing_annot.py`: `spoken=True` (only for the PDF's
  invisible text) adds the frame's characteristic symbol (`CHARACTERISTIC_CHARS`) and
  joins ⌀ to the tolerance; what is drawn does not change.
- Docs: `docs/sciforge/parity/drawings.md` (Export PDF row, the PDF/A gap row, tests),
  regenerated AI copy.

## Findings

- TechDraw's PagePrinter calls `refreshViews()` right before rendering, which deletes
  and recreates every edge item of every view (and `redrawCommand()` again afterwards).
  So nothing done to TechDraw's own edge items before printing survives into the PDF, and
  a Python reference to one is dangling afterwards: calling `setZValue` on it crashed
  FreeCAD (tried first: lifting cosmetic edges into their own marker band). Reading their
  paths before printing is safe, and the recreated items have the same paths.
- Qt writes dash patterns in units of the pen width: hidden edges and SciForge's centre
  marks are both 12:3; at equal widths they are identical in the PDF. (SciForge's centre
  marks are drawn with TechDraw's ISO dashed pattern rather than dash-dot: a separate,
  visual matter, not changed here.)
- Qt's PDF/A-1b subsets carry CIDSet; its XMP uses attributes (`pdf:Trapped="False"`,
  `xmpMM:DocumentID=...`, `pdfaid:part="1"`), PDF/X-4 adds `pdfxid:GTS_PDFXVersion`.
- veraPDF / a PDF/X preflight could not be run here (downloads blocked); conformance is
  argued from ISO 19005-1 / 15930-7 and checked object by object.
