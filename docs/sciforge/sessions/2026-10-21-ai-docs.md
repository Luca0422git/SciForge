## What was built

1. **A documentation root for AI models**, `src/Mod/SciForge/docs/ai/` (the previous agent's
   docs root: installed by CMake, carried in the Claude extension, offered as MCP resources):
   - hand-written: `README.md` (start page), `handbook.md` (what SciForge is, Fusion's ideas
     mapped to it, units and coordinates with the three planes' sketch axes, timeline and
     history marker, bodies, components and joints, sketches and profiles, ids and names,
     undo, parameters, a good way to work), `sketches.md`, `selectors.md` (the language,
     facts that matter, a tested cookbook), `checking.md`, `troubleshooting.md` (the real
     failure messages and how to recover), `recipes/` (12 recipes and an index: bracket,
     enclosure with lid, shaft with keyway, gear pair, flange with bolt pattern, threaded
     fastener, snap-fit, sheet-like part, revolved knob, lofted handle, surface patch,
     parametric plate);
   - generated by `tools/sciforge/make_ai_docs.py` (`sciforge/ai/tool_docs.py`): `tools.md`
     (every tool, linked, plus the shared rules), `reference/<tool>.md` for all 117 tools
     (what it does; every argument with type, unit, default, limits; the answer; the
     errors: what it needs and what a call without arguments is told; a complete example:
     the setup calls, the call and the real answer recorded in FreeCAD; more argument
     examples; the recipes and golden models that use it), `examples/golden-models.md` (the
     449 golden models by feature and by op, with the tools that build each op) and
     `user/`, a copy of `docs/sciforge` (every top page, `parity/`, `dev/`; not the
     sessions or briefs) so an AI can read everything Luca can, also when installed.
2. **Every example runs.** Tool calls in a ` ```json sciforge-calls ` block (each `{"tool",
   "args", "expect"}`, expect = texts, JSON paths with tolerances, a picture's size) are run
   in real FreeCAD by `SciForgeTests/headless/docs_runner.py`, one fresh session per document
   (17 documents, 320 calls). The reference examples (`SciForgeTests/docs/
   tool_examples.py`, 120 examples with setups) are run too and their answers compared with
   the recorded ones (`tool_results.json`; numbers within 1e-4; the documentation tools'
   own examples only by their first line). `SCIFORGE_DOCS_RECORD=1` records again. In
   `run_tests.sh --only headless / base`. The 3 examples that need the window (screenshot,
   set_view, get_view) are run and recorded by the new GUI scenario `ai_docs_gui`.
3. **Ways to reach it**:
   - tools `docs_search` (BM25 over every section of every document, headings and titles
     weigh more, code blocks and "See also" less; snippets and `path#anchor` addresses;
     scope a folder or a file), `docs_read` (a document, a section by anchor, or a golden
     model; pages of 12000 characters; the first page of a long document lists its
     sections; an unknown path or anchor answers the close ones), `examples_search`
     (recipes and golden models by words, tool, op, tag, kind) in `catalog/docs_tools.py`,
     work in `sciforge/ai/docs_core.py` (pure Python). The MCP server answers them itself
     (`mcp_core`), so they work while SciForge is closed and inside the Claude extension;
     in the app they run through the executor (`actions/docs_actions.py`). They come right
     after list_tools / get_help in `CHAT_ORDER` (a small local model gets them).
   - help topic `docs`; MCP instructions mention the documentation.
   - MCP resources: every document `sciforge://docs/<path>`, with `#anchor` for one
     section; `sciforge://examples/golden/{id}` (template); `sciforge://handbook` (all in one
     file), `/compact` (without the tool pages, about 170 KB) and `/full` (with `user/`).
   - the chat panel's system prompt gets a short index of the documents (about 1.5 KB; the
     prompt is 4.7 KB) and the instruction to search before guessing.
   - one file for AI apps that load files: **+ Add an AI > Save AI handbook...** (writes
     `<user data>/SciForge/ai/SciForge-for-AI.md` and opens its folder), `sciforge-cli docs
     export FILE [--compact | --full]`, `make_ai_docs.py --export FILE`. `sciforge-cli docs
     search | read | examples` too (no FreeCAD needed).
   - the Claude extension (`installers.mcpb_files`) also carries `docs_core.py` and the
     golden models; the `model_part` prompt points to examples_search / docs_search.

## Findings / bugs fixed (found by writing and testing the documentation)

- **A step that changed nothing said "Done"**: a cut from a sketch on the top face without
  `flip`, a hole from a sketch below the part, a shell thicker than the part (OpenCASCADE
  returned the plate unchanged). The executor now compares every body's volume, area, faces
  and box before and after a step tool and adds "Warning: no solid changed ... Usual causes:
  ..." (not for sketches, parameters, construction, surfaces, cosmetic threads, components;
  not while the history marker is rolled back or when steps broke).
- **Move/Copy rotate ignored `pivot`** (bodies turned about the origin axis, not the
  catalogue's "axis through pivot"): `ops/bodies_ops.py`; golden `bodies_move_rotate_pivot`.
  Found because the gear pair would not mesh.
- **Bounding boxes of free-form bodies were too big**: FreeCAD's BoundBox encloses B-spline
  control points (a 24 x 16 loft was reported 29.8 x 21.5). `geometry_facts.tight_box`
  (optimalBoundingBox on the real geometry) in every answer: the "Bodies now" summary,
  inspect_design, check_design, diff_design, get_design, physical_properties, query_geometry.
- **A surface step that failed did not say why** ("these steps failed: Surface1"): now with
  the reason ("The boundary is not closed: ...").
- **A surface body reported a volume** (FreeCAD's Volume of a lone face): now 0.
- **Deleting a parameter used by another parameter's formula was allowed** (half = w / 2,
  delete w): FreeCAD writes that reference without the container's name; `parameters.py`
  `_users_of` now finds it ("'w' is used by: the parameter half"). Also the Change
  Parameters dialog's Delete.
- Catalogue text corrected: extrude / revolve without `regions` use the outer areas with the
  inner shapes as holes (it said "every area"); `get_help` lists the docs topic.
- Facts documented (all tested): XZ's normal is -Y (so `offset` d is y = -d), YZ's +X;
  sketch on a top face has the design's X / Y; ids are not always Name+number (`Joint`,
  `Move`, `Plane`, `Component001`, `ReplaceFace`); a new design counts as unsaved; a cylinder
  face has a seam edge (5 vertical lines on a plate with a hole); fillets on straight edges
  are cylinder faces; offset-plane sketches do not follow the part, face sketches do; a
  feature inserted while rolled back shows in the bodies only at the end; the patch surface
  goes into a new body; constraint conflicts are refused with the constraint named.

## Limitations / what is next

- The reference examples are recorded on Linux with FreeCAD 1.1.4; on another platform the
  numbers could differ beyond 1e-4 (record again there if so).
- `get_view`'s recorded answer depends on the window size of the test screen (1920 x 1200).
- The user/ copies must be regenerated when docs/sciforge changes (the unit test says so):
  after merging branches that edit docs/sciforge, run `python3 tools/sciforge/make_ai_docs.py`.
- docs_search is keyword search (BM25 with a small stemmer), not semantic: synonyms the
  documents do not use are not found.
- No recipe for drawings or assemblies with moving joints (the handbook shows a joint).
