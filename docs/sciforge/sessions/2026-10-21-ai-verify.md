To be copied into MEMORY.md by whoever merges (this branch does not edit MEMORY.md).
Started from `wf/ai-tools` (d1bd37a), which builds the tool catalogue, the executor, the
headless backend and the CLI (notes: `2026-10-21-ai-tools.md`). No FreeCAD core file changed
(nothing for `core-patches.md`).

Luca's request (idea 3 of `docs/sciforge/dev/cadcraft-lessons.md`): "make the model as smart
when working in SciForge as possible". This session gives an AI agent ways to check its own
work with numbers before trusting a picture, MCP resources and prompts, an end-to-end agent
test, and documentation that cannot drift from the tools.

## What was built

1. **Five checking tools** (`sciforge/ai/catalog/verify_tools.py`, work in
   `sciforge/ai/actions/verify_actions.py`; all read-only, 114 tools now):
   - `inspect_design`: every body (valid, closed, volume, area, bounding box min / max / size,
     centre of mass, solids / shells / faces / edges / vertices, material and mass, shown),
     every timeline step (index, id, name, kind, body, state, suppressed, status, the error
     message, its values; `detail: full` adds every option as `get_step` reads them), user
     parameters, sketches (closed areas, fully constrained, conflicting constraints),
     components, joints, construction geometry, drawings, the person's selection (window
     only, with a ref per face / edge) and a summary; it answers a snapshot id ("S3").
   - `query_geometry`: the faces, edges or vertices of a body or step that a selector picks,
     with facts (type, area / length, centre, normal, axis and radius, start / end,
     direction, bounding box) and **a stable reference** for each: a selector that picks
     exactly that element by its geometry (`sciforge/ai/geometry_facts.py`: type, then normal
     / direction / radius, then "max" / "min" / a coordinate along x, y, z, checked with
     `selectors.select` itself). The ref goes straight into fillet / chamfer / shell / draft;
     `pick` is the same ready for measure / create_sketch. "of" a step gives the solid as it
     was after that step.
   - `check_design`: invalid or open solids (with OCC's reason), bodies in several pieces,
     empty / surface-only bodies, failed and warning steps, steps after a rolled-back marker,
     suppressed steps, sketches with conflicting / redundant / malformed constraints,
     objects in error outside the timeline, overlapping bodies (SciForge's Interference,
     `analysis.interference`). Answers ok, problems, warnings and the facts.
   - `render`: the picture itself (MCP image content, PNG). Views iso (Fusion's Home: front,
     right, top) / front / back / top / bottom / left / right or any direction; highlight
     faces / edges (selectors, "of" a body or step) in orange. renderer window = SciForge's
     own 3D view (the person's camera and selection are put back afterwards); software =
     **a renderer of our own** (`sciforge/ai/render_core.py`, numpy + a hand-written PNG
     encoder): flat-shaded faces with a depth buffer, hidden edges left out, shown sketches
     in blue, an X / Y / Z triad, 2x anti-aliasing, the answer says how many mm one pixel is.
     auto (default) uses the window when there is one, so **render works headless, in the
     CLI and in the MCP server's --headless mode**.
   - `diff_design`: what changed since a snapshot id, since `last_change` (the executor keeps
     a small record of the design just before every AI change that succeeds) or since a step
     id (the solid right after that step compared with now, plus the later steps): bodies
     added / removed / changed (volume, area, size, counts before / after / change), steps
     added / removed / changed (values, state, status, message, order), parameters.
   - `measure` improved (same name and arguments, b now optional): X / Y / Z distances, the
     two nearest points and what each pick is (length, radius, area, perimeter...) as JSON
     after the old sentence; only `a`: the size of that one pick.
   - Long answers of these tools are compact JSON (`bridge_core.compact_json`: short lists and
     objects on one line), far fewer tokens for the AI.
   - Help topic `checking`; the MCP instructions, the workflow help and the chat panel's
     system prompt tell the AI to check with numbers first, picture second; the checking
     tools come right after list_tools / get_help in `CHAT_ORDER` (a small local model gets
     them too).
2. **MCP resources and prompts** (`sciforge/ai/mcp_resources.py`, answered by `mcp_core`;
   capabilities resources + prompts in initialize):
   - resources: `sciforge://design` (inspect_design), `sciforge://design/check`,
     `sciforge://design/timeline`, `sciforge://tools` (the catalogue), every help topic
     `sciforge://help/<topic>`, `sciforge://docs/index` and every document under the docs root
     as `sciforge://docs/<path>`; templates `sciforge://step/{id}`, `sciforge://tools/{name}`,
     `sciforge://help/{topic}`, `sciforge://docs/{path}`. The design resources go through
     call_tool, so they work through the bridge and headless alike. Unknown URI: -32002
     with data {uri}; paths outside the docs root, hidden files and other file types are
     refused.
   - **The docs mechanism for the next agent**: the docs root is
     `src/Mod/SciForge/docs/ai/` (or `$SCIFORGE_AI_DOCS`). Any `.md` / `.txt` / `.json` put
     there (sub-folders too) is listed and readable at once; its title is its first `# `
     line. It is installed by CMake (the docs glob is now recursive) and carried in the
     Claude extension (`installers.mcpb_files`: `server/docs/ai/...`, plus
     `mcp_resources.py`).
   - prompts: `model_part` (description, material, save_as), `fix_failed_step` (step),
     `prepare_for_3d_printing` (format, path, material), `review_design`, `make_parametric`
     (sizes). Missing required / unknown arguments: -32602.
3. **Documentation that cannot drift**: `sciforge/ai/tool_docs.py` writes
   `docs/ai/tools.md` (a table of all tools in tools/list order, then a section per tool:
   Fusion command, kind, needs, description, an argument table, examples; the shared rules
   once at the end, linked); `tools/sciforge/make_ai_docs.py [--check]` writes / checks it.
   `docs/ai/README.md` (hand-written) explains the folder and the checking workflow.
4. **sciforge-cli check FILE** (exit 1 when the design has problems) and **sciforge-cli
   render FILE OUT.png [--view top] [--size 800x600]** (no window needed).

## Findings / bugs fixed

- A fillet / chamfer on edges that are smooth (the boundary of an earlier fillet) answered
  "Select the edges or faces to fillet (click them in the view)" although the AI had given
  them: `blend.trial` now says the picked edges are smooth and there is nothing to round
  (only the AI ops call `blend.trial`; the dialog is unchanged).
- A sketch on an offset origin plane stays where it is when the part below it grows (as in
  Fusion): the agent test first expected holes through 12 mm and got blind holes; it now
  sketches on the top face, which follows. Worth teaching in the next agent's docs.
- Headless, FreeCAD keeps every sketch "visible" (only the window's PartDesign hides the
  sketches a feature used): the software renderer leaves out sketches another object uses.
- `executor.forget` dropped only the builder; it now also drops the design's snapshots when
  the design is closed (`close_design`), not on delete_step.

## Limitations / what is next

- The software renderer draws flat-shaded solids, edges and sketches only: no appearances,
  no transparency, no construction planes or joints, no text in the picture.
- render with renderer window and highlight uses SciForge's selection to mark the faces, so
  a highlight on an earlier step (not shown) is not visible there (software draws it).
- Snapshots live only in this SciForge session (at most 20 per design).
- Refs are found among the body's current faces / edges; an element with no unique
  geometric description (two identical coincident edges) gets `ref: null`.
- The next agent (docs): write the documents in `src/Mod/SciForge/docs/ai/` (they appear as
  resources at once; run `python3 -m unittest SciForgeTests/unit/test_ai_docs_contract.py`
  for broken links), regenerate `tools.md` with `tools/sciforge/make_ai_docs.py` after any
  catalogue change, and update `docs/sciforge/parity/ai.md` (not touched here).
