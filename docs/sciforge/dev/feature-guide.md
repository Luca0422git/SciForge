# Building a SciForge feature (read before writing one)

SciForge copies **Fusion's behaviour** (not its assets, wording or code) on top of FreeCAD 1.1.4's
PartDesign. A feature is only done when a person can use it with the mouse without a single error
in the Report view, and a scenario test proves that with real clicks.

## Where code goes

- `src/Mod/SciForge/sciforge/<name>_ui.py`: the command + dialog. Define a module-level
  `COMMANDS = {"SciForge_Name": CommandClass}`; every `*_ui.py` with `COMMANDS` is registered
  automatically (`commands._feature_commands`). No edit of `commands.py` needed.
- `src/Mod/SciForge/sciforge/<name>.py`: the geometry/document logic without Qt (callable from
  the golden-model builder and unit tests).
- The ribbon already points at the SciForge names, with FreeCAD's command as fallback, e.g.
  `("SciForge_Fillet", "PartDesign_Fillet")` in `ribbon_config.py`. Once your command exists the
  button and its key (`config.PREFERRED`) run yours. For an item that is still `None` (greyed),
  change that one line to your command name.
- Icons: `sciforge/icons/ui/<icon>.svg` (generated by `tools/sciforge/make_icons.py`); reuse the
  existing ones named in `ribbon_config.py`.

## The dialog: `taskui.Panel`

Subclass `taskui.Panel` (see `extrude_ui.py`, `presspull_ui.py`, `construct_ui.py`):

- `__init__(doc, transaction)` opens one undo transaction; OK commits, Cancel/Esc aborts and
  recomputes. Fill `self.layout` (a QFormLayout), call `self.finish_layout()`.
- `feature()` returns the object being built, so OK refuses to close on an invalid result and
  shows FreeCAD's error text in the dialog (like Fusion keeping its dialog open).
- `schedule()` recomputes 60 ms later (coalesces drags). Never recompute inside a click handler.
- `cleanup()` removes your draggers/observers/overlays; call `super().cleanup()`.
- Starting another command finishes yours (`commands.finish_open_dialog` calls `finish()`).
- `_close()` clears the selection (Fusion does; a leftover selection was re-used by the next
  command and destroyed the part) and leaves edit mode safely.

Widgets: `taskui.DistanceField` (unit-aware, can `bind(obj, prop)` so `=Parameters.x` works),
`taskui.ArrowDragger(origin, direction, distance, size, on_drag, on_release)` (blue drag arrow).

Value boxes (Fusion shows the value beside every handle): give the dialog
`self.value_boxes = taskui.ValueBoxes(self, default="distance")` and, after making a handle,
`self.value_boxes.attach(handle, "distance", lambda: field.widget.text(), commit)` where
`commit(text)` takes what was typed (a `preview.FormulaInput(...).take(text)`, or
`field.take(field.parse(text))`). Call `self.value_boxes.discard()` in `cleanup()`. Every
handle class is a `taskui.BoxCarrier` (`ArrowDragger`, `extrude_ui.AngleDragger`,
`handles3d` handles, `primitives_ui.LinearHandle`, `revolve_ui.AngleHandle`): a new handle
implements `box_geometry()` (anchor, tail, tip, half-width in mm) and calls `follow_box()`
from its poll and `drop_box()` in `remove()`. The box never covers a handle of the dialog
(`arrow_box_core.spot`). Digits typed with the mouse over the 3D view go into the current
box by themselves (`taskui.TypeOverView`, installed by `Panel`); a dialog without a box can
name a field with `typing_field()`. Size a handle for the screen with
`taskui.handle_size_at(view, point, hi=...)` (about 75 px for the arrow, whatever the part).

Picking:
- Sketch profiles: `profile_pick.ProfilePicker(view, sketches, on_pick)` shades closed regions and
  picks a click inside one. `profile_pick.ray_plane(view, pos, base, normal)` for your own maths.
- Planes/faces: `sketch_ui.sketch_target()` (selected origin/datum plane or planar face),
  `sketch_ui.origin_planes(body)`.
- Selection: install a `Gui.Selection` observer whose `addSelection` only does
  `QtCore.QTimer.singleShot(30, self._selection_changed)`; do the work there.
- Body: `commands.find_body()` (active body, or the selection's/first body, made active);
  `commands.ensure_body()` creates one if needed.

## Rules (each one cost a broken release)

1. **Never use pivy callbacks** (`dragger.addMotionCallback`, `SoEventCallback` via pivy): pivy
   runs Python without the GIL and FreeCAD segfaults. Mouse events: FreeCAD's
   `view.addEventCallback("SoMouseButtonEvent"/"SoLocation2Event", fn)` (GIL-safe); remove with
   `view.removeEventCallback`. Draggers: poll with a QTimer (`taskui.ArrowDragger`).
2. **Never build, recompute or remove objects inside a selection observer, Coin event callback
   or dragger callback.** Defer with `QtCore.QTimer.singleShot`.
3. **Never call `Gui.ActiveDocument.resetEdit()` on a sketch** while a sketch tool may be active:
   it crashes FreeCAD 1.1. Use `commands.leave_edit()` (runs `Sketcher_LeaveSketch`).
4. **`face.normalAt(u, v)` already points out of the solid**, also for faces whose `Orientation`
   is "Reversed". Do not flip it again.
5. `body.newObject()` does not move `body.Tip` for every feature type: set `body.Tip = feature`.
   Set `Refine = True` on PartDesign features (Fusion never shows seam faces).
6. Distances are signed along the outward normal / sketch normal, like Fusion: into the part is
   negative; extruding into material auto-switches to Cut unless the user chose an operation.
7. Every SciForge log line starts with `[SciForge]` (`from . import log, warn`). Never let an
   exception escape a command, timer, observer or event callback: catch and `warn()`.
8. A command that cannot start says why next to the mouse (`commands.tell(msg)`), never silence.
9. No modal pop-ups for things Fusion does in its dialog (sides of a polygon, attachment mode,
   "select something first"). Wait in the task panel for the user to pick instead.
10. One command = one undo step (the Panel's transaction does this).
11. **A `QTimer.singleShot(ms, obj.method)` is silently cancelled when `obj` (a Qt object) is
    deleted first**, e.g. a widget with `WA_DeleteOnClose` that you close right before. Keep
    the widget alive (hide it) until the call ran, or call a plain function.
12. Python only, unless there is no Python route. A change to FreeCAD's own files needs a
    `SCIFORGE:` comment, an entry in `docs/sciforge/core-patches.md`, **and** a Python-side
    fallback/workaround: core patches only reach the user with a full rebuild.

## Tests you must add

- **Scenario** `SciForgeTests/gui/scenarios/<name>.py` using `SciForgeTests/gui/harness.py`:
  only real input (`h.ribbon("Fillet")`, `h.press("f")`, `h.click(App.Vector)`,
  `h.drag(...)`, `h.task_button("OK")`), then `h.check(...)` on the model (volume, faces, bbox,
  visibility). The harness fails the scenario on **any** Report-view error, SciForge warning or
  traceback, after every step. Click one step **after** the key/button that opened a task panel
  (the panel narrows the 3D view). Call `h.fit()` before computing click points. Click edges
  with `h.click_edge(point)` (it aims within a few pixels like a person does; the CI's software
  renderer rounds differently and a plain click on an outline edge hit the face next to it).
  The command dialog floats over the right of the view and is wider on some machines (fonts):
  `h.click`, `h.click_edge` and the corner click pan the view first when it covers the point
  (`h.uncover`); a failed check's note says what was on top. Cover: the happy
  path, editing the feature again (double-click it in the timeline, or `Gui.ActiveDocument.setEdit`
  if that is how the timeline does it), Cancel leaving the model unchanged, undo/redo, and the
  "nothing selected yet" start. Import `QtTest` from `PySide6` (FreeCAD's `PySide` shim has
  none); a scenario that does not load fails with "the scenario file loads".
- **Golden models** (`SciForgeTests/golden/models/*.json`, format in its README) for any new
  geometry, with hand-derived expected volume/area/faces/bbox. Extend `builder.py`/`schema.py`
  with a new op if needed (builder must call your Qt-free module, the same code the GUI uses).
- **Unit tests** for pure logic.

Run (FreeCAD is already unpacked at the path below in this sandbox):

```
tools/sciforge/run_tests.sh --freecad <FC> --out <OUT> --scenario <name>   # one scenario
tools/sciforge/run_tests.sh --freecad <FC> --out <OUT> --only golden
tools/sciforge/run_tests.sh --freecad <FC> --out <OUT>                     # everything
tools/sciforge/run_tests.sh --freecad <FC> --out <OUT> --only base         # all but scenarios
tools/sciforge/run_tests.sh --freecad <FC> --out <OUT> --only scenarios --shard 2/4  # CI's split
```

Format with black, line length 100. Look at the screenshots your scenario saves (`<OUT>/*.png`)
to check it looks like Fusion.
