
## Rules for every SciForge builder (read these files first, in this order)
- `CLAUDE.md`, `MEMORY.md` (the HANDOFF section, Decisions, Known issues, the latest session logs), `docs/sciforge/feature-outline.md` sections 0-5 and the section of your area, `docs/sciforge/dev/feature-guide.md`, `docs/sciforge/plan.md`, and the parity docs your area touches (`docs/sciforge/parity/*.md`).
- **Research Fusion's behaviour before building anything** (web search: Autodesk Fusion help pages, Autodesk blog/Learn courses, Autodesk Community forum answers, tutorials; autodesk.com may only be readable through search excerpts). Write a behaviour spec with sources (mark each row Autodesk / Forum / Guess) at the top of your parity doc. Copy behaviour, never assets, wording or code.
- New code goes in `src/Mod/SciForge/sciforge/` (Qt-free core with unit tests in `SciForgeTests/unit/`, commands/dialogs in `*_ui.py` with `COMMANDS = {...}` so they register automatically). Avoid FreeCAD core changes; if one is unavoidable it carries a `SCIFORGE:` comment and an entry in `docs/sciforge/core-patches.md`, and you say so in your report (it then needs the 3-hour full build).
- Every log line is prefixed `[SciForge]` (`from . import log, warn`). No exception may escape a command, timer or event handler. Never lose a user's work: a refusal says why and what to try.
- The ribbon (`ribbon_config.py`): change only the lines of your own entries (wire the greyed or raw-FreeCAD items of your area to your commands); do not reformat other lines (other agents edit the same file at the same time).
- The main branch you start from has every area of the first plan merged: components (`App::Part`; contract in `docs/sciforge/parity/components.md`; new bodies through `commands.find_body()` / `ensure_body()`, which pass over a body that does not exist yet at the history marker), versions (Ctrl+S on a saved design opens a version prompt: a scenario that saves presses Ctrl+S then calls `versions_input.accept_save()`), Insert/Export, Fusion selection (box select, Select Other, filters: `selection_ui.py`; a press near any live drag handle is that handle's drag, never a box: a handle class derives from `taskui.BoxCarrier` and its poll calls `follow_box()`), value boxes beside every handle (`taskui.ValueBoxes`), handles drawn on top (`taskui.on_top_root(coin, place)`, the SoTransform stays child 0), joints, the sketch tools (`sketch_draw*.py`), Text and Emboss, direct modeling (Capture Design History off), the MESH and SURFACE tabs, INSPECT analyses and the navigation bar, Derive / Decal / Preferences / Scripts, the DRAWING workspace (`drawing*.py` on TechDraw), and the known gaps of sf/gaps (Thin Extrude, Join away = New Body, Loft ends, ...). Read the parity doc of your area to the end: its last section lists what is missing. Five agents build at the same time (wave 5): sketch-2 (chain select, project to surface, 3D sketch, sketch polish), exchange-2 (STEP with structure, IGES / DXF export, insert manipulators), surface-2 (surface and loft options), polish-2 (value boxes on Move / Scale / Draft handles, the floating check, timeline groups, versions milestones, Derive structure) and mesh-inspect-2 (mesh edit environment, face groups, inspect gaps). Stay out of the others' areas; when two areas meet, the brief says who owns it. Wave 4 (merged) built: radius sets / variable / rule / full round fillets; Move/Copy and Copy/Paste of components and component patterns; Component Drag, Motion Link, Contact Sets, Motion Study; sketch chamfer types, NPT and fastener holes, Extrude To Object extend options, Objects To Cut for Revolve / Sweep / Loft; pattern Compute Adjust, draft parting line, multi-body shell / draft / scale, Move Object Faces, Press Pull Offset Type; drawing tolerances, GD&T, sheets, sections, breakouts. Luca's bug fixes (merged after wave 4): a body pattern / mirror copies the body's last solid step before it in the timeline (`Source`, with the body's name in `SourceBody`), rolls back with the marker and keeps its copies when the original is deleted (sf/fix-pattern-bodies; a step added at a marker right before a step outside the bodies goes in before it: `timeline_ops.rank_before_marker_step`); a sketch opens with FreeCAD's Show support off and the design shown as it is at the sketch's place in the timeline (`sketch_ui.show_design_at`, sf/fix-sketch-face); a decal follows its face (`decal.follow()`, sf/fix-decal); a click on a face while extruding ends the extrusion there (`extrude_to_face*.py`, sf/fix-extrude-to-face). Keep their scenarios (`fixpattern_*`, `fixsketch_*`, `fixdecal_*`, `extrudeface_*`) passing when you touch those files.
- A check on a position reached by dragging compares with tolerances or with the value the drag actually produced, never an exact number (CI's window differs by a pixel: CI #121).
- The harness never starts a step while a document recomputes (a step fired inside a long recompute loses its clicks and keys); `harness.idle_step()` waits inside a step list. The grid's minor lines default to 5 subdivisions (2 mm): a scenario that clicks on 1 mm points sets 10 first (`grid_ui.put("Subdivisions", 10); grid_ui.apply_subdivisions()`). Compare measured numbers with tolerances (CI's window differs by a pixel, DXF keeps a few decimals).
- The test harness resets the selection mode and filters before each scenario (a CI shard shares one settings profile across its scenarios). If your area adds a setting remembered between sessions that changes how clicks or views behave, reset it the same way in `harness.run`'s `prepare()`, or a scenario after yours in a CI shard inherits it.
- Never end your turn while one of your test runs is still going: wait for it (a Bash command run in the background that exits when the run ends notifies you), then act on the result.
- **Tests with the real FreeCAD 1.1.4**: `LC_COLLATE=C tools/sciforge/run_tests.sh --freecad <your FreeCAD folder (tools/sciforge/get_freecad.sh)> --out <your own scratch dir> --scenario a,b,c` and `--only unit`. Scenarios go in `src/Mod/SciForge/SciForgeTests/gui/scenarios/<area>_*.py` with real mouse and keyboard input (8+ paths: the main use, every option, edit from the timeline, undo/redo, save/reopen, Esc/Cancel, a refusal with a clear message, an empty design, components). When you change a behaviour other code relies on, grep every scenario that uses it and update and run them. Before finishing, run the scenarios of every area you touched, plus `--only base` (unit, golden, smoke, journey).
- The machine has 4 CPUs shared with about five other agents: run scenarios one at a time, never the full suite; a scenario that times out under load is re-run alone before you conclude anything.
- Lint: `/root/.local/bin/black -l 100 <files>`; `/root/.local/bin/flake8 --max-line-length=100 --extend-ignore=E203,E741 <files>`.
- Work only in your worktree. Create and commit on your branch. NEVER push. NEVER use git stash. Do not touch other worktrees.
- **Do NOT edit MEMORY.md** (every branch editing it conflicts at the merge): write your session-log entry (what you built, FreeCAD facts and traps, gaps) to `docs/sciforge/sessions/<your area>.md`.
- Before finishing: re-read your whole diff adversarially, fix what you find, run your scenarios again.
- Report: branch, commits, each scenario with its check count and result, what Fusion does that you did not build and why (with evidence where the kernel or FreeCAD is the limit), and a plain-language summary for Luca (a beginner) of how to use it.
